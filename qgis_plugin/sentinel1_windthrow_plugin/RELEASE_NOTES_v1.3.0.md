# Release Notes — Sentinel-1 Windthrow Detector v1.3.0

Дата: 17.10.2026. Предыдущая версия: 1.2.2. Релиз **«refactor-only»**:
научная логика, пороги, формат результатов и сообщения об ошибках не
менялись. Все изменения — внутреннее устройство кода (слоистая
архитектура), типизированные интерфейсы, CI и диагностика, выполненные
по плану улучшений (batches B1–B5).

## Что изменилось

### 1. Слоистая архитектура `sources/`

Монолиты `windthrow.py` (1071 строка) и `coh_delta.py` (1116 строк)
разобраны на модули с односторонними зависимостями (без циклов):

| Модуль | Строк | Содержимое |
|---|---|---|
| `constants.py` | 121 | единый источник всех числовых дефолтов со ссылками на бумагу |
| `numpy_ops.py` | 214 | 10 чистых numpy-хелперов (индекс, порог, морфология) |
| `raster_utils.py` | 342 | GDAL-хелперы: сетка/warp/растеризация/полигонизация |
| `hyp3_utils.py` | 462 | парсинг HyP3-продуктов, burst-валидация, водная маска |
| `pipeline.py` | 347 | общий постпроцессинг: threshold → filter → mask → polygons |
| `types.py` | 158 | дата-классы `DetectionResult` / `ForestSafeguard` |
| `errors.py` | 74 | иерархия типизированных исключений |

Детекторы похудели: `windthrow.py` 1071 → 647, `coh_delta.py`
1116 → 647. Постпроцессинг обоих радарных режимов теперь идёт через
один код `pipeline.py` — устранена строка-в-строку дубликация
(исключён источник расползания пороговой логики).

### 2. Типизированные результаты и ошибки

* Детекторы возвращают `DetectionResult` — дата-класс с
  `to_dict()`, воспроизводящим прежний dict **байт-в-байт**
  (все ключи легаси сохранены); класс также работает как read-only
  Mapping, поэтому существующий код с `result["wi"]` / `result.get(...)`
  продолжают работать без изменений.
* `forest_safeguard` в когерентном режиме — типизированный
  `ForestSafeguard` (flagged/flags/reasons/zone/coh_prepost_mean/
  forest_share).
* Новая иерархия ошибок: `WindthrowPluginError` → `InputValidationError`
  (он же `ValueError` для совместимости) → `ProductMismatchError`;
  `DataAccessError`; `CancelledError` (наследник — прежний
  `OperationCancelled`). Смешение семейств HyP3 / разные burst-футпринты /
  рассогласование поляризации теперь кидаются как
  `ProductMismatchError` с теми же текстами.

### 3. Диалог: обработка ошибок (UX)

* Отмена детекции пользователем показывает «Detection was cancelled»
  (в v1.2.2 было окно «failed» с пустым текстом — легаси-баг).
* Типизированные ошибки плагина показывают короткий человекочитаемый
  текст + «Details in the QGIS log»; полный трейсбек — в лог, как и
  раньше. Предупреждение предохранителя «вне_леса@Y» осталось
  неблокирующим.

### 4. Диагностика и CI

* 11 «тихих» блоков best-effort-очистки (удаление временных растров,
  temp-каталогов, вычисление статистики) теперь логируются на уровне
  info — сбои клинапа видны, ошибки детекции по-прежнему не глотаются.
* GitHub Actions CI: job на контейнере GDAL 3.10.3 (полный набор
  тестов + coverage-артефакт) и pure-numpy job (38 IO-free тестов без
  растрового стека). Оба зелёные на релизном коммите.
* Новый хелпер `choose_chunk_rows` (адаптивная высота чанка, clamp
  128–2048) — готов, в циклы пока не вживлён (дефолт 512 строк не менялся).

## Совместимость

* Формат результатов (dict-ключи), тексты ошибок, прогресс-сообщения и
  метки порогов — без изменений; прежние импорты из `windthrow` /
  `coh_delta` работают через реэкспорты (проверено assert-identity).
* Замороженные научные дефолты не тронуты: WI = ΔVV + ΔVH (DiD по
  Rüetschi et al. 2019), адаптивный порог 2,9 дБ, когерентность
  0,6/0,3, min_pixels 27 (10 м) / 6 (80 м), доля леса 0,3,
  предохранитель coh_pre > 0,6 → «вне_леса@Y».
* Тесты: 165 (v1.2.2) → 179; из легаси-тестов не изменён ни один.
