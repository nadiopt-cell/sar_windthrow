# План тестирования плагина Sentinel-1 Windthrow Detector на реальных данных

Версия документа: 1.0 (v0.7.0)

## 0. Общая схема

Тестирование разбито на 4 уровня, каждый следующий использует результаты
предыдущего:

| Уровень | Что проверяем | Данные | Инструменты |
|---------|---------------|--------|-------------|
| T0 | Корректность математики | синтетика (в комплекте) | `pytest tests/` |
| T1 | Работоспособность в QGIS | 2–3 сцены, 1 область | QGIS ≥ 3.28 |
| T2 | Детектирование на реальном ветровале с проверкой | База ветровалов Шихова и др. (2020) | QGIS + плагин |
| T3 | Чувствительность параметров a / n | тот же кейс | плагин, серия запусков |

---

## T0. Юнит-тесты (без QGIS)

```bash
python -m pytest tests -v          # из папки, в которой лежит sentinel1_windthrow_plugin/
```

72 теста: формула WI и знак («ветровал = рост обратного рассеяния»),
адаптивный порог, фильтр малых объектов, медианный фильтр с NaN,
автосопоставление поляризаций по имени файла, конверсия DN→dB; при
наличии GDAL — сквозной прогон на синтетических сценах (композит → WI →
порог → маска → векторизация с атрибутом area_ha, растровая и векторная
маска-ограничитель).

## T1. Smoke-тест в QGIS

1. Установить ZIP (Plugins → Install from ZIP), убедиться, что появились
   панель «Sentinel-1 Windthrow» и меню.
2. AOI — небольшая область (20×20 км): «Draw on map» → Search (GRD,
   ~1 месяц) → Download Selected (1–2 сцены). Проверить прогресс,
   отмену и докачку.
3. Preprocess: dB + Lee(5) на скачанных файлах.
4. Windthrow: 1 сцена «до» + 1 «после» (можно соседние даты без шторма —
   детекций быть почти не должно: проверка уровня ложных тревог).
5. Убедиться, что на карту загружаются `_wi.tif`, `_mask.tif` и
   `<base>.gpkg`, а в таблице атрибутов заполняется `area_ha`.

## T2. Основной кейс — реальные ветровалы Европейской России

### 2.1 Источник эталона

База событий ветровала в лесной зоне Европейской России 1986–2017 гг.:

> Shikhov A.N., Chernokulsky A.V., Azhigov I.O., Semakina A.V.
> A satellite-derived database for stand-replacing windthrow events in
> boreal forests of European Russia in 1986–2017.
> Earth Syst. Sci. Data, 12, 3489–3513, 2020.
> DOI статьи: 10.5194/essd-12-3489-2020
> Данные (polygons, 102 747 элементарных участков / 700 событий):
> https://doi.org/10.6084/m9.figshare.12073278

База содержит дату (или диапазон дат) каждого события, тип шторма
(конвективный / торнадо / неглубокий циклон) и контуры повреждений —
это готовый эталон для расчёта PA/UA.

Связанная работа для приоритизации участков (та статья, на которую вы
сослались): Шихов А.Н., Абдуллин Р.К., Семакина А.В. Картографирование
подверженности лесов гибели от пожаров и ветровалов (на примере
территории Урала) // Геодезия и картография. 2020. № 4. С. 19–30
(DOI: 10.22389/0016-7126-2020-958-4-19-30). Карта подверженности
полезна как слой приоритизации зон мониторинга, но эталоном для T2
служит именно база figshare — в ней есть даты и контуры.

### 2.2 Выбор тестового события (критерии)

Из базы выбрать события, удовлетворяющие ВСЕМ условиям:

1. **Дата в эпоху Sentinel-1**: ≥ 01.10.2014 (лучше ≥ 2016, когда
   работали S1A+S1B и частота съёмки максимальна). В базе период
   2016–2017 валидировался по Landsat/Sentinel-2 — эти годы наиболее
   надёжны.
2. **Площадь события** ≥ 2 км² (заметно на 10 м сетке при min 0.5 га).
3. **Летний шторм** (июнь–август): зимние/осенние события со снегом
   между датами съёмки дают ложные сигналы в SAR (снег поглощает
   C-диапазон) — их использовать только как дополнительный стресс-тест.
4. В AOI должны быть проходы **Asc** и **Desc** — выбрать то направление,
   у которого ближе к дате шторма есть снятия «до» и «после».

В базе к Уралу привязаны, в частности, события июля 2012 и октября 2016
(Средний Урал; октябрьское — снеговое, годится только как стресс-тест).
Для основного кейса удобнее летние события 2016–2017 гг. из лесной зоны
(Пермский край, Кировская обл., Удмуртия, Коми) — их в базе много и они
перекрыты RTC-архивом Planetary Computer.

### 2.3 Настройка запуска (рекомендации)

| Параметр | Значение |
|----------|----------|
| AOI | bbox контура события из базы + буфер 5 км |
| Продукт | **RTC** (γ⁰) для Среднего Урала и хребтов; GRD допустим на равнине |
| Окно «до» | шторм − 21 … − 1 день (набрать 1–5 сцен одного направления) |
| Окно «после» | шторм + 1 … + 14 дней (идеально — первое же снятие; чем позже, тем выше риск сенокоса/сплошных санитарных рубок в кадре) |
| Орбита | одна (Asc ИЛИ Desc) для обоих окон |
| Поляризация | VV+VH (по умолчанию) |
| Preprocess | dB + Lee(5) |
| Параметры детекции | a = 2.9 дБ, медианный фильтр 3×3, n = 27 px (пока не оценена чувствительность) |
| Маска леса | если есть слой лесов (например, векторный лесопокрытый контур или маска из Global Forest Change) — включить; без маски ожидаемо больше ложных тревог на полях |

### 2.4 Оценка качества (object-based, как в статье-первоисточнике)

1. Обрезать контуры событий из базы по AOI (элементарные участки
   агрегировать до полигонов событий, исключить класс «пожар», если он
   есть в слое).
2. Совместить с результатом плагина (`<base>.gpkg`).
3. Посчитать контингентную таблицу: объект детекции = **TP**, если он
   пересекает хотя бы один эталонный полигон; FP — не пересекает ни
   одного; FN — эталонный полигон ≥ 0.5 га, не пересечённый ни одним
   объектом детекции.
   - PA = TP / (TP + FN)
   - UA = TP / (TP + FP)
   Дополнительно сравнить суммарную площадь (Σ area_ha плагина против
   площади эталона) и распределение размеров объектов.
4. Визуальная проверка в QGIS: WI-растр (стиль Singleband pseudocolor),
   маска, эталон — в одной группе; пройтись по FP/FN и записать причину
   (поле/вода/снег/рубка/дата съёмки).

Ориентир для признания кейса успешным: PA ≥ 0.7 и UA ≥ 0.5 по объектам
≥ 0.5 га при наличии маски леса (в оригинальной статье PA 0.85–0.88,
UA 0.65–0.81; в boreal-условиях при меньшей густоте снятий ожидаемо
скромнее).

## T3. Чувствительность параметров

На том же кейсе прогнать сетку:

- a ∈ {2.8, 2.9, 3.1, 3.35} (адаптивный режим)
- n ∈ {20, 25, 27, 30} px

Свести таблицу PA/UA (как Figure 9 в статье). Убедиться, что тренды
совпадают со статьёй: ниже a/n → выше PA, выше a/n → выше UA. Выбрать
рабочую пару параметров и внести её в Settings как значения по
умолчанию для вашего региона.

## Дополнительные (опциональные) проверки

- **Стресс-тест на смешении дат**: взять пост-сцену через 3–4 недели —
  доля FN должна вырасти (начавшиеся рубки, зарастание) — подтверждает
  окно «≤ 2 недель».
- **GRD vs RTC**: один кейс на обоих продуктах; сравнить количество
  ложных тревог в зонах рельефа (склоны Среднего Урала).
- **Орбиты**: Asc и Desc по отдельности; сравнить PA/UA.
- **Снеговой кейс** (октябрь 2016, Средний Урал): ожидаемо сильное
  ухудшение — задокументировать как ограничение.

## Реестр известных источников ложных тревог

| Источник | Механизм | Смягчение |
|----------|----------|-----------|
| Поля / сенокос / пахота | рост шероховатости поверхности | маска леса |
| Водные объекты | ветровое волнение между датами | маска леса/суши, порог a выше |
| Сплошные рубки в междудатном интервале | тот же рост рассеяния | контроль даты пост-сцены (раньше = лучше) |
| Свежий снег | поглощение C-диапазона → «потемнение» | не использовать зимние пары |
| Флэт-зоны радара (layover/shadow на GRD) | геометрические искажения | продукт RTC |

## Что фиксировать в отчёте по каждому кейсу

1. Событие из базы (ID, дата, тип шторма, площадь).
2. Список сцен S1 (ID, даты, направление, продукт).
3. Параметры запуска (a, n, медианный фильтр, маска).
4. Контингентная таблица, PA, UA, суммарные площади.
5. Список FP/FN с предполагаемыми причинами.
6. Замечания к UX плагина (ошибки, неочевидные шаги) — для следующей
   итерации.
