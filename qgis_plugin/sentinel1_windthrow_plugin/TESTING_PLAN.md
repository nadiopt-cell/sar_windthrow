# План реального тестирования плагина Sentinel-1 Windthrow Detector на реальных данных

Версия документа: **2.0 (v1.2.1)**, 06.09.2026. Заменяет версию 1.0 (эра v0.7.0).
Синхронизирована с METHOD.md (§3b, §7), RELEASE_NOTES_v1.1.0/1.2.0/1.2.1 и отчётом изд.9.

## 0. Что изменилось с версии 1.0 (v0.7.0)

Инструкция v1.0 описывала единственный тогда режим — амплитудный WI. За проектом
закрепились три режима детекции, 12 верифицированных событий 2015–2017 с
расчётными метриками и два вывода, изменивших приоритеты тестирования:
(а) амплитудный C-диапазон на лесных событиях Европейской России не детектирует
ветровал (AUC ≈ 0,5) — режим референсный, не основной; (б) рабочий тракт —
интерферометрическая когерентность с DiD-метрикой и L-диапазон PALSAR.

| Уровень | Было (v1.0, v0.7.0) | Стало (v2.0, v1.2.1) |
|---------|---------------------|----------------------|
| T0 | 72 теста | **144 теста** (+GFC-маска, burst-пары, водная маска) |
| T1 | Smoke: Search/Preprocess/WI | + проверка coh-вкладки, GFW GFC-маски (v1.2.1: доступна и в coh-режиме), About 1.2.1 |
| T2 | WI-детекция с PA/UA | **Три тракта**: T2-C (когерентность DiD 80 м — основной), T2-B (бёрст-пары 40 м — новое v1.2), T2-L (PALSAR); WI — T2-W референсный |
| T3 | Сетка a/n для WI | + сетки для coh (a_coh, min_pixels под шаг сетки) |
| Эталон | «выбрать событие из базы Шихова» | 12 верифицированных событий с эталонными AUC (прил. Б) — регрессионная проверка |

Главные новинки, подлежащие реальному тестированию: **бёрст-пары 40 м**
(INSAR_ISCE_BURST, «позиция роадмапа v1.2» изд.9), **маска GFW Hansen GFC на год,
предшествующий событию** (v1.1; правило эпохи), **конвенция водной маски 1 = суша /
0 = вода** (v1.2 — фикс латентного бага v1.0/v1.1), **валидация DiD-пары
«тот же бёрст»** (v1.2) и исправление GUI v1.2.1 (источник маски снова доступен
в режиме когерентности).

## 1. Подготовка

### 1.1 Установка плагина

1. QGIS **≥ 3.28**.
2. Модули → Manage and Install Plugins → **Install from ZIP** →
   `plugin_dist/sentinel1_windthrow_plugin_v1.2.1.zip` (копия — в `download/`).
3. Проверка версии: меню Plugins → Sentinel-1 Windthrow → About →
   **«Version 1.2.1»**.
4. Регрессия v1.2.1: вкладка Windthrow Detection → Detection method =
   «Coherence DiD» → чекбокс «Restrict detection to forest mask» → в списке
   «Mask source» должны быть доступны **«GFW Hansen GFC»** и «Custom file»
   (до v1.2.1 комбо сбрасывалось в «Custom file» и блокировалось — валидированный
   воркфлоу coh + GFC@Y был недостижим из GUI).

Зависимости в комплекте QGIS (numpy/scipy/GDAL); pip не нужен. Нужен интернет:
Planetary Computer (STAC), /vsicurl/ чтения Hansen GFC (без аутентификации).

### 1.2 Учётные записи и ресурсы

| Ресурс | Назначение | Примечание |
|--------|------------|------------|
| Earthdata Login (urs.earthdata.nasa.gov) | доступ к ASF | бесплатная регистрация |
| ASF Vertex (search.asf.alaska.edu) | заказ HyP3 INSAR | тариф Basic: 8000 кредитов/мес; INSAR-GAMMA 80 м = 10 кр/пара; burst-пара = 1 кр на заказ из 1–4 пар; после волны-2 оставалось 7710 кр |
| HyP3-продукты | coh_delta | **истекают ~30 дней** (наши — 17.09 / начало 10.2026): скачанный ZIP хранить локально, ~1,5 ГБ на событие |
| База Шихова и др. 2020 (ESSD) | эталон PA/UA/AUC | CSV в `data/shikhov_csv/`; figshare DOI 10.6084/m9.figshare.12073278 |
| 12 верифицированных событий | регрессионный эталон | `gis/windthrow_sites_map_gfw_2026-09-04_v3.geojson`, GPKG-детекции — `gis/detections_gpkg/` |

### 1.3 Юнит-тесты (T0)

```bash
python -m pytest tests -v   # из папки над sentinel1_windthrow_plugin/
```

144 теста. Запускать интерпретатором **с GDAL** (в QGIS-окружении всё на месте):
на python без GDAL file-level тесты пропускаются, а
`test_find_correlation_tif_zip_without_corr_raises` даёт ложный FAIL
(RuntimeError вместо FileNotFoundError) — это среда, не код.

## 2. T1 — дымовой тест в QGIS (0,5–1 ч)

1. Установить ZIP (п. 1.1), убедиться в тулбаре/меню.
2. AOI 20×20 км на знакомом лесном районе: «Draw on map».
3. Search & Download: продукт **RTC**, одно направление орбиты, 2 даты без шторма →
   Download Selected (проверить прогресс/отмену/докачку).
4. Preprocess: dB + Lee 5.
5. Windthrow Detection: метод WI, adaptive a = 2.9, медианный 3×3, min 27 px → Run.
   Проверить: `_wi.tif` (или `_wi_norm.tif`), `_mask.tif`, `<base>.gpkg` c `area_ha`.
6. Маска: источник **GFW Hansen GFC**, GFC event year = год пост-даты − 1…
   год пост-даты; убедиться, что строятся `_forest_gfc<Y>.tif` (окно 1° ≈ 40 с/слой
   по /vsicurl/ — ожидаемо, не зависание).
7. Пара без шторма: детекций быть почти не должно (уровень ложных тревог).

**Критерий прохождения:** все выходы на карте, GPKG читается, GFC-маска
строится, сообщений об ошибках в Log Warnings нет.

## 3. T2-C — когерентность DiD, полные кадры 80 м (основной тракт)

### 3.1 Данные

Пары ASF HyP3 **INSAR_GAMMA, looks 20×4** (шаг 80 м): три даты одного
прохода g1 < g2 < g3; prepost = g1+g2 (окно содержит шторм), контроль = g2+g3
(вне окна повреждения, тот же сезон). На 12 верифицированных событий продукты
уже скачаны (репо/локальный архив, ~4,5 ГБ) — новый заказ не нужен. Для нового
события: Vertex → On Demand → INSAR_GAMMA → granules [g1, g2] и [g2, g3],
looks 20×4, опциональные слои по вкусу (водная маска включается всегда).

### 3.2 Настройка GUI (Windthrow Detection)

| Поле | Значение |
|------|----------|
| Detection method | Coherence DiD — HyP3 InSAR |
| Pre/post pair | папка/ZIP prepost-продукта (или путь к `*_corr.tif`) |
| Control pair | папка/ZIP контроля (обязателен: без него скор деградирует до 1 − coh) |
| Threshold mode | Adaptive |
| Offset a (adaptive) | **0,25** (единицы когерентности; 8–14 % ложных тревог на валидации; 0,10 фладит сцены с сезонным дрейфом) |
| Median filter | 3×3 |
| Min object size (px) | **6** (80 м: 0,64 га/px → объект ≈ 3,8 га) |
| Restrict detection to forest mask | вкл., Mask source = **GFW Hansen GFC**, GFC event year **Y = год шторма** → строятся обе маски `_forest_gfc<Y>.tif` (кандидаты) и `_forestbg_gfc<Y>.tif` (фон) |

### 3.3 Запуск и результаты

Выходы: `_dcoh.tif` (dcoh = coh(контроль) − coh(prepost), положительный над
ветровалом), `_mask.tif`, `<base>.gpkg`; в логе — диагностика `pixel_size_m`,
`product_flavors`, `min_object_area_ha`, состояние водной маски (конвенция
HyP3: 1 = суша, 0 = вода; маска «>50 % воды» игнорируется с предупреждением).

### 3.4 Ожидания и критерии

Регрессия по 12 событиям (прил. Б): DiD-AUC 0,44–0,93, среднее 0,618–0,625;
рекорды ID683 (0,928), ID694 (0,908), ID674 (0,764). Кейс ID654 — заведомо
отрицательный (полигон безлесный на дату события). Объектная проверка —
пересечение GPKG с эталонным контуром; скриптовый расчёт AUC — по образцу
`pipeline/validate_v1_coh.py` / `scripts_screening/wave2_coh_delta.py`.

## 4. T2-B — бёрст-пары 40 м (главный тест кампании, новое в v1.2)

### 4.1 Когда нужен

След уже «зернистости» полного кадра: узкие торнадо-треки (ID694, 161 га;
ID696), где кадр 250 км даёт долю повреждений 1–2 %. Бёрст ~50–150 км²,
шаг сетки 40 м (10×2 looks), пиксель 0,16 га. Экономика: 1 кредит на заказ
из 1–4 пар против 10 кр за пару INSAR-GAMMA.

### 4.2 Заказ в Vertex (вручную; помощник заказа — в роадмапе)

1. Vertex → поиск типа **SLC-Burst** по AOI и датам; выбрать бёрст (карточка
   бёрста: трек, относительный burst ID, поляризация) — запомнить имя.
2. On Demand → **Burst InSAR** (INSAR_ISCE_BURST): reference = дата до шторма,
   secondary = дата после; **looks 10×2** (→ 40 м; 5×1 = 20 м, 20×4 = 80 м);
   имя задания вида `id694-burst-prepost`.
3. Второй заказ — **контроль на ТОМ ЖЕ бёрсте**: reference/secondary — обе даты
   вне окна повреждения (тот же сезон), имя `id694-burst-control`.
4. Дождаться готовности (~1–2 ч), скачать оба ZIP **сразу** (ссылки истекают).

### 4.3 Настройка GUI

Как T2-C, отличия: prepost/control — ZIP бёрст-продуктов; **min object size
20–25 px** (0,16 га/px; плагин сам подсказывает, когда эффективная площадь
объекта падает ниже 2 га); маска GFC@Y строится на сетке DiD бёрста.
Плагин валидирует пару: контроль обязан быть **тем же бёрстом** (совпадение
relative burst ID, трека, поляризации), иначе отказ с сообщением «order the
control pair for the same burst»; смешение GAMMA-кадра с бёрстом запрещено;
несовпадение шага (40 м против 80 м) — предупреждение.

### 4.4 Критерии успеха

След торнадо покрыт детекциями по всей длине (не фрагментами по краям сетки
80 м); AUC/пересечение с эталоном не хуже 80-м прогона того же события;
в result присутствуют `pixel_size_m = 40`, `product_flavors` с бёрст-семейством.

## 5. T2-L — L-диапазон PALSAR (подтверждающий тракт)

Данные: годовые мозаики ALOS/ALOS-2 PALSAR (HH/HV, Planetary Computer,
alos-palsar-mosaic) — «pre» = год, предшествующий событию, «post» = год события;
файлы подаются в Pre/Post-списки вкладки (DN → дБ конвертируется автоматически).
Настройки: метод **L-band decline**, adaptive **a = 1,5–2,0** (годовые пары, не
2,9!), медианный 3×3, min 27 px, маска GFC@Y **обязательна**. Ожидания по
валидации: invAUC 0,870 (dHH, ID666), 0,905 (dHV, ID694); физика — падение
сигнала над завалом (знак уже инвертирован в LDI). Годовая пара = 12 месяцев
между эпохами: конфаундеры (рубки/зарастание между годами) отсекаются маской.

## 6. T2-W — амплитудный WI (референсный тракт)

Протокол PA/UA инструкции v1.0 (объектная оценка по эталону figshare: TP/FP/FN,
PA = TP/(TP+FN), UA = TP/(TP+FP), ориентир PA ≥ 0,7 / UA ≥ 0,5) сохраняется в
качестве приложения к старому документу. Скорректированы ожидания: на лесных
событиях Европейской России летом C-band-амплитуда не детектирует (ID666:
AUC 0,49–0,51, PA 0,059 — конфаундер влажности), поэтому тракт используется
для сравнения с когерентностью и мониторинговых прогонов, а не как основной.
Рабочие параметры прежние: RTC, adaptive a = 2,9, медианный 3×3, min 27 px,
нормализация фона вкл., маска леса вкл.

## 8. Реестр известных ложных тревог и грабель

| Источник / ситуация | Механизм | Смягчение |
|---------------------|----------|-----------|
| Поля/сенокос/пахота | рост шероховатости | маска леса (GFC@Y) |
| Водные объекты | ветровое волнение | водная маска HyP3 (1 = суша / 0 = вода), порог выше |
| Свежий снег / листопадная инверсия | поглощение / сезонный скачок когерентности | контроль того же сезона; медиана фона в пороге |
| Сезонный дрейф когерентности (freeze-up) | сдвиг всего фона dcoh (ID694: +0,33) | adaptive по **медиане**, a ≥ 0,25; не снижать до 0,10 |
| Контроль, загрязнённый тем же штормом (derecho ID666) | фон декоррелирован в любой паре | контроль из тихого периода / до-до пара; принимать AUC 0,6 как предел для таких кейсов |
| Узкий след < шага сетки | размывание 80-м пикселем | бёрст-пары 40 м (T2-B) |
| Маска «из будущего» (WC-2021 на событие 2017) | 0 px фона (ID655) | ретроспектива 2001–2024 → GFC@Y; WC — только мониторинг |
| Внутригодовая рубка до шторма (ID654) | GFC ежегодная | сверка с lossyear/визуально; кейс — отрицательный контроль |
| Ссылки HyP3 истекли | presigned URL ~24 ч / продукты ~30 дней | скачивать сразу после готовности |
| /vsicurl/ «завис» | чтение GFC окнами | ~40 с/слой на окно 1° — норма |
| min_pixels по умолчанию на 40 м | 6 px = 0,96 га (< валидированных 3,8 га) | 20–25 px для бёрст-пар (подсказка в логе при < 2 га) |

## 9. Фиксация результатов и порядок кампании

**Форма по кейсу** (JSON/таблица): ID события, дата, тип, площадь эталона;
версии плагина и QGIS; продукты (имена гранул, семейство, шаг); параметры
(a, a_coh, min px, маска + Y); выходы (# объектов, Σ area_ha, AUC при
скриптовом расчёте); предупреждения из лога; скриншоты (dcoh, маска, GPKG
поверх эталона). Складывать в `results/` репо (`<id>_realtest_<дата>.json`),
скриншоты — в `docs/realtest/`.

**Рекомендуемый порядок:**

1. **Неделя 1:** T0 → T1 → T2-C на 1–2 событиях из 12 (сверка с прил. Б) →
   регрессии R1–R7.
2. **Неделя 2:** T2-B — заказ бёрст-пар в Vertex на ID694 и ID696 (≈ 4 кредита),
   прогоны 40 м, сравнение с 80-м прогоном изд.6.
3. **Неделя 3:** T2-L на ID666/ID694; T2-W по желанию; свод результатов.
