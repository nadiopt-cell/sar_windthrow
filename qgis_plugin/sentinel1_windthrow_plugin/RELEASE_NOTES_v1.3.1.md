# Release Notes — Sentinel-1 Windthrow Detector v1.3.1

Дата: 18.10.2026. Предыдущая версия: 1.3.0.

Релиз **аддитивный**: научная логика по умолчанию не меняется, поведение
v1.2.2 воспроизводится бит-в-бит. Добавлен один новый параметр (по
умолчанию выключен) и один существующий параметр выведен в GUI.

## Что изменилось

### 1. Пространственное усреднение поля Δcoh — `smooth_size`

NaN-устойчивое усреднение (box mean) поля Δcoh выполняется **до**
медианного фильтра и порога. Смысл: когерентность одной 12-дневной пары
несёт шум оценивания порядка 0.20 единиц когерентности — это того же
порядка, что и сам ветровальный сигнал, поэтому порог `медиана + a_coh`
без усреднения помечает 8–14 % кадра (тысячи объектов на сцену).
Усреднение по N пикселям делит шум на √N и, поскольку ветровальный очаг
существенно шире одного 80-метрового пикселя, **повышает** разделимость
классов.

* Дефолт `smooth_size = 1` — **выключено**; поведение v1.2.2 не меняется.
* Гало чанка растёт до `max(median_size, smooth_size) // 2`, поэтому
  чанкованный и полный проходы дают идентичный результат (есть тест).
* Окна со суммарной долей валидных пикселей меньше 0.30 дают NaN.
* Новый хелпер: `numpy_ops.box_mean_nan`.

### 2. Минимальная площадь объекта в GUI

Спинбокс «мин. площадь» уже был доступен в API (`min_pixels`), но
в диалоге когерентного детектора его роль не была видна. Теперь рядом
со сглаживанием явно выбирается и площадь: 32 га на 80 м — именно этот
фильтр (а не сглаживание) даёт основную очистку карты.

### 3. Новый элемент GUI

`Spatial averaging (dcoh):` — None (off) / 3 × 3 — 240 м / 5 × 5 — 400 м.
По умолчанию None. Подсказка описывает шум √N, ожидаемый выигрыш AUC
и предупреждение о целях уже окна.

### 4. Тесты

Добавлено 6 тестов: на `box_mean_nan` (выключенный режим, NaN-устойчивость,
мало валидных пикселей, подавление спекла), на `threshold_pass` со
сглаживанием (сохранение блоба, подавление спекла), на совпадение
чанкованного и полного проходов и на дефолт детектора. Полный прогон —
186 passed.

## Измеренный эффект (23 события нового датасета Шихова, `vetrovaly_3316`)

Средние; порог `a_coh = 0.25` не менялся, менялись только сглаживание
и минимальная площадь. Подробности — `testing/ОТЧЁТ_вариантА.md`.

| метрика | как есть (3.8 га) | 3×3 + 32 га | 5×5 + 32 га |
|---|---|---|---|
| AUC кольцо 2–10 км | 0.720 | 0.755 | 0.772 |
| число объектов (на сцену) | 12 282 | 1 124 | 896 |
| PA по объектам | 0.296 | 0.203 | 0.176 |
| ложные срабатывания по сцене | 6.7 % | 4.0 % | 3.7 % |

Абляция показывает, что почти вся потеря полноты приходится на фильтр
по площади (12 282 → 1 283 объекта при PA 0.199), а усреднение 3×3
поверх него **бесплатно и даже слегка полезно** (PA 0.203, PA по
пикселям 0.303, AUC 0.755). Окно 5×5 даёт лучший AUC, но хуже полноту
по узким очагам: для датасета с контурами шириной 1–3 пикселя при 80 м
рекомендуется 3×3.

## Когда сглаживание включать не надо

Если ожидаемая ширина ветровального контура меньше ~2 пикселей продукта
(тонкие шкваловые полосы), усреднение разбавляет цель: держите
`smooth_size = 1` и переходите на 20-метровые Burst InSAR продукты.
